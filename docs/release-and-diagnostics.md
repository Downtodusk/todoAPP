# 构建、签名与诊断交付

## 0.4.1 包的选择

- **已有此前测试版：选 Debug 更新包** `dist/todo-0.4.1-debug.apk`。它沿用本工作区的开发签名，版本号升至 6，适合直接覆盖安装并保留现有待办与设置。
- **全新安装或已有同一 Release 身份的安装：选 Release 包** `dist/todo-0.4.1-release.apk`。开启 R8 与资源裁剪，使用独立的本地发布签名，不是开发签名。
- 两者包名均为 `com.example.todo`，签名不同，**不能互相覆盖**。不要为切换包而卸载含有重要待办的安装：当前不提供数据迁移/备份导入，卸载会删除本地数据。此时继续使用 Debug 更新包。
- 所有 APK 都是待验收版本，签名正确不等于真机可靠性、AI 准确率或性能已验收。已知 OPPO 重启恢复失败仍按用户要求暂缓处理。

## 签名身份

工作区已创建独立 RSA 3072 位发布身份。私钥在忽略版本控制的 `signing/todo-release.jks`，凭据在忽略版本控制的 `keystore.properties`；目录权限 700，文件权限 600。**请将这两项一起安全备份**，不要提交、上传或发送到公开位置。以后所有 Release 更新必须复用此身份；开发签名另在项目的 Android 用户工具目录中，也应保留以支持已有测试安装更新。

首次在全新工作区创建新应用身份才运行：

```bash
source scripts/android-env.sh
python3 scripts/create-release-key.py
```

脚本拒绝覆盖已有身份，不打印密码；签名密码通过临时私密文件传给 keytool，不放在进程参数中。对已有安装继续发布时，应恢复原签名文件与配置，不能重新生成密钥。私钥不是工具缓存，不存入可随时清理的 `.tools/`。

```bash
source scripts/android-env.sh
./gradlew :app:assembleRelease
bash scripts/package-apks.sh
```

缺少签名配置时 Release 构建会明确失败。Debug 与独立性能变体仍可构建。打包脚本在 `dist/` 生成两个 APK、SHA256SUMS、证书验证报告、源码版本信息及 R8 映射文件；不会连接或安装到任何手机。保留与每次 Release 对应的映射文件，才能分析混淆后的调用位置。不要把映射文件或证书验证成功当作运行测试通过。

## 崩溃诊断

- 应用捕获未处理异常，将最多 5 条记录保存在私有目录，随后仍交由系统的原异常处理器结束进程。
- 仅保存时间、应用版本、API 级别、异常类及有限调用帧。排除异常消息、线程名、文件路径、suppressed 消息、待办字段、原文、URL、密钥和请求/响应体。嵌套原因和大小均有上限。
- 设置 → 导出日志，由系统文件选择器让用户决定位置；没有自动上传，也不申请存储权限。设置 → 清除诊断日志只删除诊断记录。
- 无记录时也可导出一个版本/系统概要。OOM、进程被系统直接终止、原生崩溃、ANR 等不保证能由 Java 未捕获异常处理器记录。
- `allowBackup=false` 并补充 Android 12+ 云备份和设备传输排除规则，避免凭据密文与本机 Keystore 脱离后迁移。规则依据 [Android 自动备份文档](https://developer.android.com/identity/data/autobackup)。

自动测试校验敏感消息/文件路径不出现、原因循环有界、最多保留 5 条、导出及清理。系统文件选择器和崩溃后重启的设备路径仍待真机验收。

## 后续人工反馈建议

正常使用中可先检查添加/编辑/滑动撤销、深浅色与动画降级，再试分享导入和 BYOK 预览。反馈时给出步骤、预期/实际表现、应用版本；若应用崩溃，可以附上导出的诊断文件。无需提供 API Key 或完整工作通知。

提醒的重启缺陷、Doze/省电/时区场景及其他品牌，均沿用已有测试矩阵的未通过/待测标记。用户当前不方便测试，因此没有继续操作已连接的手机。
