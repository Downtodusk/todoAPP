# 0.4.2 动效 A/B 对比包

两种构建共享功能、数据模型及签名，versionCode 均为 7，versionName 分别为 `0.4.2-A`、`0.4.2-B`。只改变详情转场，保留 0.4.1 已完成栏目不留时间空位、时间滚轮、中英文及个性配色。可以依次覆盖安装同签名 APK，不必卸载。设置页显示版本后缀。默认构建 B，用 `-PdetailMotion=A` 构建 A；这不是新增设置项，也不写入用户偏好。

## A：保留 0.4.0 容器展开／收回

恢复与来源条目绑定的共享容器、300ms 的原边界轨迹及原淡入淡出／返回缩放。首页和全部待办分别匹配来源，避免跨列表错误配对；没有可见来源的通知跳转使用普通转场。

原来整个 Scaffold 每帧按条目大小重新测量。本版用 `skipToLookaheadSize()` 将内部日历、标题和表单固定在最终布局尺寸，只让外层容器边界变化并裁切；没有重新引入单独的标题共享缩放。保留原容器运动方向及节奏，表单不再随着高度变化重排。减少动态效果时仍关闭共享容器。

参考：[Android 共享转场尺寸与裁切](https://developer.android.com/develop/ui/compose/animation/shared-elements/customize)。

## B：0.4.1 进入 + 随手势缩小及纵向收回

- 进入沿用 0.4.1 的 220ms、24dp 详情平移、8dp 列表平移及 90ms 淡出交接。
- 使用系统 `PredictiveBackHandler` 处理左右边缘返回；随系统进度等比缩小，最小为原尺寸 90%，横向跟随最多 12dp，圆角逐渐到 28dp。进度只在绘制层读取，不逐帧重测表单。
- 松手确认后，上下边界向中间收拢 200ms，通过圆角裁切而不是压扁文字；只在末段淡出。点击顶部返回、保存或删除也使用相同收拢流程，重复返回不重复出栈。
- 松手取消后 180ms 恢复，保持编辑草稿与滚动位置。时间等弹窗先处理自己的返回；键盘返回由系统正常处理。
- 列表离开前只截取一次内存预览，拖动期间不截图／读回像素，也不把预览写到磁盘。预览不接收输入；真正返回后恢复可交互列表。通知直达／重建后无预览时使用主题底色。
- 减少动态效果仍为短淡入淡出；旧系统无逐帧返回进度时执行普通返回收拢。手机是否分发完整预测性返回事件仍需实测。
- 返回动画期间若通知打开另一个详情，旧动画只能弹出自己的导航项，不能误关刚打开的事项。

参考：[Android 预测性返回](https://developer.android.com/develop/ui/compose/system/predictive-back-setup)。模拟器中的回调注入证明应用响应路径，不代替 OPPO 真机手势验收。

## 验证

- A、B 各完整运行 API 36 instrumentation：40 项通过、1 项手动场景工具按设计跳过（runner 显示 `OK (41 tests)`）。
- 追加并发通知保护后，B 的左右手势、弹窗／保存和返回中打开新详情专项 3/3 通过。
- A、B 在 360dp / 130% 字号下的布局与标题转场专项各 2/2 通过，测试后恢复原屏幕密度和字号。
- 两构建各 JVM：55 项通过、1 项真实模型测试按设计跳过；Lint 0 errors、25 warnings、1 hint。
- 覆盖正常／减少动态效果的长标题固定尺寸、已完成不留空、两侧返回取消／确认、草稿不误保存、时间弹窗先关闭、保存只返回一次，以及完整原有数据／提醒／语言／配色回归。
- 首轮 B 手势专项暴露两处测试接入问题：活动 dispatcher 不会把事件发到独立 Dialog 窗口，改用系统 Back；尺寸检查节点需位于变换层内，才能读到变换后的边界。修正后专项及完整回归通过。未通过的首轮日志保留，不计入通过结果。
- 实际渲染采样：[A 进入](ui-0.4.2/A-enter.png)、[A 返回](ui-0.4.2/A-return.png)、[B 左侧拖动](ui-0.4.2/B-left-drag.png)、[B 右侧拖动](ui-0.4.2/B-right-drag.png)、[B 松手收回](ui-0.4.2/B-retract.png)、[B 取消恢复](ui-0.4.2/B-cancel.png)。采样毫秒数是测试时钟，不是实际渲染延迟。

独立 API 36 x86_64 模拟器、1080×2400、420dpi、字体 100%、SwiftShader；仅连接本地 ADB 15038。未操作用户手机、未处理已明确暂缓的重启提醒问题。

## 同轮性能对照

同一模拟器顺序运行原版 0.4.0、A、B，每版 R8 + `CompilationMode.Full()`、10 轮 × 3 次往返。测量期间不并行编译，原始 0.4.0 APK 来自 d2405c1，APK 哈希与原始结果存于 [对照记录](performance-0.4.2/comparison.json)。这轮重新测量了旧版，不混用上一轮 0.4.1 的数值。

| 指标（ms，越低越好） | 原版 0.4.0 | 0.4.2-A | 0.4.2-B |
| --- | ---: | ---: | ---: |
| 帧 CPU 耗时 P50 | 47.42 | 43.76 | 23.02 |
| 帧 CPU 耗时 P95 | 92.76 | 60.83 | 37.61 |
| 帧超期时间 P50 | 46.93 | 41.38 | 7.72 |
| 帧超期时间 P95 | 111.14 | 64.26 | 29.85 |

A 保持 300ms 原轨迹，P95 CPU 耗时下降约 **34.4%**；B 使用不同的进入／收回流程，下降约 **59.5%**。帧样本数分别 935 / 1095 / 1060，不能把样本数当 FPS。模拟器仍有超期帧；没有宣称真机 60/120fps、全局掉帧率达标或完成 Baseline Profile。

帧测量 APK 的哈希在对照 JSON 中；测量后补充了“返回动画期间收到新详情”的导航归属判断，此防护不改变正常动画几何与时序，性能数据未重测该并发通知情形。

本 benchmark 使用点击进入和普通 Back 返回，衡量整次导航；左右边缘预测性返回的进度／取消／确认由独立仪器测试覆盖。两者都不能代替 OPPO 系统实际手势分发和主观手感的手机验收。

原始数据：[0.4.0](performance-0.4.2/0.4.0-benchmarkData.json)、[A](performance-0.4.2/0.4.2-A-benchmarkData.json)、[B](performance-0.4.2/0.4.2-B-benchmarkData.json)。完整 trace、构建和 instrumentation 日志保留在忽略目录 `.tools/performance/ui042/`。
